# App-only in-place installer — private development

Historical dev12 boundary. The approved dev13
[changed-package follow-up](package-delta-installer-plan.md) supersedes the
VIPP-only and mandatory first-copy limitations below.

The user requests Fresh, copied Replacement and real in-place updates, plus
separate removal of inactive duplicate host installations. Build dev12 is
unreleased. Source and qualification use isolated worktrees and disposable
prefixes; existing installations and their active update sessions are protected.

## Boundaries

- `INCREMENTAL` retains its serialized meaning: hash/copy dependencies into a
  replacement. It is now labelled Replacement, not a true in-place update.
- `IN_PLACE` changes only a pure Python VIPP wheel in the current generic
  `cpu`/`cuda13` prefix. Existing dependency versions, Python, entry-point mappings
  and shortcut locations must remain compatible and unchanged. Hash-addressed
  GPU roots cannot change their full-wheel identity.
- Automatic prefers in-place when eligible, otherwise explains Replacement or
  Fresh. An explicit unavailable method blocks instead of silently falling back.
- Legacy apps do not honor a maintenance lock. One normal replacement installs
  a pinned early runtime hook; installing a marker into an existing legacy app
  is forbidden. Protocol migrations also need a replacement.

## Live update protocol

`_runtime_lease.py` runs before version/UI/scientific imports, using only the
standard library. OS locking serializes process lease registration and durable
maintenance. Live or unknown processes block in-place; new launches fail closed
while maintenance is active. Suspended acceptance children have one-use permits
bound to actual Windows process birth/image/parent facts, including the precise
venv redirector/base-Python pair. No environment-variable bypass exists.

`inplace.py` assesses metadata compatibility without copying dependencies,
hashes only VIPP's owned app/metadata/launchers, and stages the exact wheel with
validated RECORD and direct-URL metadata. Scripts retain identical paths/bytes.
Foreign/unowned/overlapping content, native app payloads, changed app files,
reparse/hardlinks and unsafe archives refuse in-place.

`inplace_execution.py` has a distinct typed, durable journal. It never supplies
the current prefix to candidate rollback/recovery. Token authority is persisted
before maintenance; complete old/new app manifests precede atomic exchanges.
Only the app and its own dist-info are moved. Dependencies are not recopied or
claimed freshly payload-integrity-verified. Ordinary acceptance plus an exact
owned-prefix import still run. Ownership is the commit point; environment path,
installation ID, base runtime and unchanged package inventory stay stable.

Recovery restores only exact app trees before commit, or completes the bound
registration after commit, preserving conflicts rather than overwriting them.
All restoration conflicts are preflighted before mutation. Backup deletion is
resumable only within the exclusive app workspace; relaxed subset deletion is
never used on live app trees. Finalization is journaled before startup unblocks,
so ordinary generated bytecode cannot strand an otherwise accepted app.

## Qualification and cleanup

Focused fixtures cover the selector, compatibility, script/ownership drift,
app exchange kill boundaries, stale consent, foreign files, cancellation and
Windows process coordination. Actual package-free disposable venv tests exercise
the real redirector and whole app-only engine. Test this before building a
development installer; no host install or global PATH change is authorized here.

Inactive host cleanup is a separate exact-target operation: current, in-use,
pending, rollback and shared runtimes are not garbage. Preserve original data,
user sessions, AI/source branches/worktrees, download caches and evidence.
Do not rewrite current ownership/registry merely to prune old version names.
Record exact removed paths and conservative space accounting; no deletion is
inferred from a source-only test or from a directory's age.

Evidence: `VIPP-local-tests/inplace-installer-20261024` beside the repositories.
Failed development receipts remain failures; final qualification must bind the
actual final source and artifact bytes rather than claim preparation as proof.
