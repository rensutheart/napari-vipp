# Changed-package in-place updates — private development

The dev13 follow-up supersedes the dev12-only eligibility limits in
[the historical app-only plan](inplace-installer-plan.md). It is untagged and
unpublished. Companion user instructions are in the separate manual worktree.

## Required behavior

Automatic selects in-place only for an authenticated compatible generic managed
CPU/CUDA installation with verified idle/startup exclusion. Existing compatible
dependencies stay at their installed versions. An installed-aware pip dry run
resolves required changes only after approval; it is not an upgrade-everything
operation. Verified cached exact wheels are reused. No pip install/uninstall
command runs against the live environment.

For a first legacy upgrade, a journal-bound same-volume prefix rename removes
ordinary launch paths without copying any dependency. Exact process identities,
module mappings and query-only Restart Manager resource users must establish
quiescence. Unknown process facts, including ambiguous same-base interpreters,
fail closed. No process is closed by setup. These checks do not claim a security
boundary against hostile foreign interpreters or arbitrary embedding programs.

Changed wheels stage off-prefix. Exact old/new RECORD unions, metadata, namespace
claims and immutable wheel hashes define file-level exchanges and rollback.
Unchanged dependency payloads retain their identities and timestamps. Native
payloads within supported wheel layouts are allowed only after in-use checks;
new/changed launcher mappings or unsupported data layouts require another route.
Python/base-runtime/ABI/track migrations are not in-place transactions.

Before canonical paths return, a pinned earliest `.pth` guard and canonical-bound
maintenance state block ordinary same-prefix Python/VIPP starts. An exception
cannot be swallowed by Python's site hook. Actual suspended acceptance children
receive one-use PID/birth/parent/image-bound permits. The installer displays a
do-not-open warning and an actionable close/recheck popup for positive running
users; inaccessible/ambiguous facts are separate blockers, not invented proof
that a VIPP window is running. Replacement/Fresh can stage separately.

## Commit and recovery

`package_delta_execution.py` uses a distinct typed schema dispatched before any
new-candidate deletion/recovery handler. Old/new ownership, prefix identity,
offline name/run/token, package manifests and small startup-control backups are
bound before exclusion. Every file exchange is an atomic rename. Rollback
preflights the complete changed union, retires exact new files into a private
discard, restores old files and controls offline, then restores canonical paths.
Unknown content is preserved; live prefix recursive deletion is never permitted.
Ownership publication is authoritative even if its writer subsequently raises.
Accepted recovery completes registration/cleanup rather than reporting rollback.

Before the first payload exchange, inspect caches for every touched old/new
Python source: `-B` suppresses cache writes, not reads. A newly generated or
changed cache refuses the transaction without deleting it. Prepared/excluding
recovery with the exact old owner/original prefix and empty mutation workspaces
restores the canonical name as-is, after static capsule/scope authentication.
Its pre-exchange phase remains durable through staged-only cleanup, so a second
interruption cannot misclassify late old-app bytes as partially installed files.
After exchanging begins, strict exact-byte rollback/conflict checks still apply.

Small original/new control metadata can remain as diagnostic evidence beside
the transaction. Full dependency environments are not duplicated by in-place.
Changed-package payload backups are removed only after acceptance or exact
restoration. Existing conservative Fresh-sized free-space checks remain; this
development does not yet advertise a fully delta-sized storage budget.

## Qualification

Require primitive/corruption/cancellation/rename-boundary tests; real tiny
disposable Windows legacy upgrades, startup exclusion, required dependency/cache
reuse, failed acceptance rollback and actual native resource checks. Injected
process inventories do not prove a whole-host scan. Keep native/scientific/GPU
lifecycle claims separate. No existing installation, OS/global PATH, AI work,
user window, public release or old cleanup operation may be changed by tests.

Evidence and actual exits live in the sibling
`VIPP-local-tests/package-delta-installer-20261024` directory. A source or test
preparation is not a completed product check, build or publication.
