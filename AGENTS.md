# Working in napari-vipp

- Read `CONTRIBUTING.md` for development checks and scientific-behavior requirements.
- Use `docs/planning.md` for active priorities, `docs/architecture.md` for
  runtime/schema invariants, and `docs/developer-notes.md` for extension points.
- `docs/README.md` indexes local plans, implementation records, and evidence.
- Public user instructions live only in the separate `vipp-mkdocs` repository.
  Read `docs/documentation.md` before a documentation change. The former local
  user guides are relocation notes, not editable copies of the manual.
- For user-visible changes, update the manual's relevant task/reference pages
  and flag unreleased behavior. If its checkout is unavailable, identify the
  missing companion update in the handoff rather than duplicating it here.
- Keep executable examples, tests, scientific contracts, release procedures,
  and development/agent context with this repository.
